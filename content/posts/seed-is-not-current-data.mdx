화면에 국가 코드가 `NL`로 그대로 노출되는 걸 국가명(`Netherlands`)으로 바꾸는 작업이었어요. 코드에서 이름을 어디서 가져올지 정해야 했습니다.

## 후보가 셋이었어요

1. 다국어 파일에 있는 국가명 목록
2. 국가 목록 API (DB 테이블)
3. 브라우저에 내장된 기능

2번을 확인하려고 **초기화 SQL 파일**을 열었습니다.

```sql
INSERT INTO countries (name, code) VALUES
  ('Malaysia', 'MY'), ('Philippines', 'PH'), ...   -- 6개국
```

6개국뿐이고 `NL`이 없었어요. 1번 목록도 25개국인데 역시 `NL`이 없었습니다.

그래서 **"두 소스 다 NL을 못 푼다"**고 결론 내리고, 3번 브라우저 기능을 쓰는 계획을 세웠어요. 코드베이스에 쓴 적 없는 기능이라 "도입 위험"까지 문서에 적었습니다.

그리고 이렇게 썼어요.

> "NL은 이 드롭다운으로 선택할 수 없는 값이니, 관리자가 수동으로 입력했거나 과거 경로로 들어온 것으로 **추정**된다."

## 추정이 틀렸어요

사용자가 그 드롭다운에서 **직접 골랐습니다.**

그 드롭다운은 2번 API 응답을 그대로 그려요. **목록에 Netherlands가 떴다는 건 테이블에 NL이 실제로 있다는 뜻**입니다.

**초기화 SQL은 처음 한 번의 스냅샷일 뿐이에요.** 그 뒤로 운영 데이터에 국가가 계속 추가돼 있었습니다.

## 더 나쁜 게 있어요

저는 **같은 작업 앞부분에서 이미 이 점을 짚어놨었습니다.**

"목록에 Netherlands가 떴으니 실제 DB엔 더 추가돼 있다"고 써놓고, 몇 시간 뒤 다음 작업에서 **초기화 파일 기준으로 되돌아갔어요.**

<Callout>
알고 있던 걸 잊은 게 아니라, **새 작업을 시작하면서 코드에 있는 것부터 다시 봤기** 때문이에요. 코드는 눈앞에 있고 운영 DB는 안 보이니까요.
</Callout>

## 왜 이렇게 되나

코드 저장소에 있는 데이터 파일은 이런 이름을 갖고 있어요.

```
seed.sql
initial_data.sql
V1__init.sql
```

전부 **"처음"**이라는 뜻인데, 읽을 때는 "이 테이블의 내용"으로 읽힙니다. 특히 그 파일 말고 다른 참고할 게 없을 때 그래요.

## 남은 것

- **초기화 SQL은 t0 스냅샷이에요.** 현재 데이터가 아닙니다. 운영에서는 계속 추가됩니다.
- **화면에 뜬 목록이 DB의 진짜 내용이에요.** 드롭다운에 있으면 테이블에 있는 겁니다.
- **"추정"이라고 적었으면 확인할 방법을 먼저 찾아요.** 추정이라고 표시하는 건 정직한 거지만, 확인 가능한 걸 추정으로 남기면 그냥 안 한 거예요.
- **앞에서 알아낸 걸 뒤에서 잊어요.** 새 작업을 시작하면 눈앞의 코드부터 다시 보게 됩니다. 중요한 판단은 적어두고 다음 작업 시작할 때 다시 읽어야 해요.

## 아직 모르는 것

- 운영 DB를 직접 못 보는 상황에서 마스터 데이터를 확인하는 방법
- 초기화 파일에 "이건 초기값일 뿐"이라고 적어두면 다음 사람이 덜 걸릴지
