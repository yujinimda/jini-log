서블릿 하나를 브라우저에서 확인하는 단계예요. 코드는 다 썼고 띄우기만 남았습니다.

프론트에서는 `pnpm dev` 하나면 됐는데, 자바는 아니었어요.

## `mvn package` 하면 뜨는 줄 알았어요

세 개가 다 다른 일이었습니다.

| 명령 | 하는 일 |
|---|---|
| `mvn package` | WAR **만들기** (`target/board.war`) |
| `cp ... webapps/` | 톰캣에 **넣기** |
| `catalina run` | 톰캣 **켜기** |

`mvn package`는 만들기까지예요. 만든 WAR이 톰캣 폴더로 안 가면 아무 일도 안 일어납니다.

그리고 **파일을 고칠 때마다 `mvn package`를 다시 해야 해요.** WAR은 그 시점의 복사본이라서 원본을 고쳐도 WAR 안은 안 바뀝니다.

<Callout>
톰캣 설정에 `autoDeploy="true"`가 있으면, 켜져 있는 상태에서 WAR을 덮어쓰면 알아서 다시 배포해줍니다. 그래서 터미널을 두 개 씁니다 — 하나는 톰캣이 로그를 뿜으며 잡고 있고, 다른 하나에서 빌드하고 복사해요.
</Callout>

## WAR이 어디 있는지 몰랐어요

`target/` 안입니다. Maven이 만드는 결과물 폴더고, 프론트의 `dist`나 `.next` 자리예요. 소스가 아니라 만들어진 거라서 `.gitignore`에 넣습니다.

```
target/
├── board.war        묶인 파일
├── board/           같은 내용을 폴더로 풀어놓은 것
└── classes/         컴파일된 .class
```

WAR은 배포용으로 묶은 압축 파일이에요. 톰캣 `webapps`에 넣으면 톰캣이 알아서 풀고 같은 이름 폴더가 생깁니다.

개발할 때는 보통 압축하지 않아요. 폴더 그대로 두고 톰캣이 그 폴더를 바로 읽게 합니다. 매번 압축하고 푸는 게 느려서요. **압축이든 폴더든 안쪽 구조는 같습니다.**

## `WEB-INF`가 뭘 하는 폴더인지 몰랐어요

"WAR로 묶이는 것들을 관리하는 폴더"라고 생각했는데 아니었습니다. WAR 안에 들어가는 건 `WEB-INF` 밖에도 있어요.

기준은 하나예요. **브라우저가 직접 열 수 있느냐.**

```
myapp/                 ← 이게 통째로 WAR가 됩니다
├── index.html         주소로 바로 열 수 있어요
├── css/, js/, img/    열 수 있어요
└── WEB-INF/           ← 브라우저가 못 엽니다. 서버만 봐요
    ├── web.xml
    ├── classes/       내 자바 클래스
    └── lib/           라이브러리
```

`WEB-INF` 안의 파일은 주소를 직접 쳐도 안 열려요. 톰캣이 막습니다. 그래서 자바 클래스와 설정 파일을 여기 둡니다 — 소스가 노출되면 안 되니까요.

여기서 이어지는 게 **JSP 위치**예요. JSP를 `WEB-INF` 밖에 두면 사용자가 주소로 직접 열 수 있습니다. 안에 두면 반드시 서블릿을 거쳐야 해요. "서블릿이 받고 JSP가 그린다"는 규칙을 지키려면 안에 둬야 합니다.

## `WEB-INF/lib`이 비어 있어서 이상했어요

`pom.xml`에 라이브러리를 두 개 넣었는데 WAR 안에는 `lib` 폴더가 아예 없었어요. `provided` 때문이었습니다.

톰캣이 이미 서블릿 API를 갖고 있어요.

```
/opt/homebrew/opt/tomcat@9/libexec/lib/servlet-api.jar
```

`provided`는 **"컴파일할 때만 쓰고 WAR에는 넣지 마"**라는 뜻이에요. 안 그러면 내 WAR에도 같은 게 들어가서 톰캣 것과 두 개가 되고 충돌합니다.

## 내 코드 에러인 줄 알았던 게 남의 앱 응답이었어요

브라우저에 이게 떴습니다.

```json
{"code":"INTERNAL_ERROR","message":"서버 오류가 발생했습니다."}
```

톰캣 에러가 아니었어요. **톰캣은 HTML 에러 페이지를 줍니다.** 저건 JSON에 한글 메시지였어요.

8080을 다른 앱(제 다른 프로젝트)이 잡고 있었고, 톰캣은 아예 못 떴던 겁니다. 브라우저 요청이 그 앱한테 갔고, 그 앱이 준 500이었어요.

포트 충돌일 때 톰캣 로그에 나오는 줄은 이겁니다.

```
Address already in use
```

<Callout>
**에러 응답의 모양을 보면 누가 답했는지 알 수 있어요.** Content-Type이 JSON인지 HTML인지, 메시지가 한글인지. 이걸 안 봤으면 내 코드를 계속 뒤졌을 거예요.
</Callout>

톰캣 포트를 8081로 바꿨습니다. 8080은 자바 진영 기본 포트라서 계속 부딪혀요.

## 남은 것

- **`pnpm dev` 하나로 되던 게 자바에서는 세 단계예요.** 만들기·넣기·켜기. 나중에 IDE가 이걸 자동으로 해주는데, 한 번 손으로 해봐야 뭘 대신해주는지 압니다.
- **에러 응답을 보면 누가 답했는지 알 수 있어요.** 내 서버가 안 떴는데 다른 서버가 대신 답할 수 있습니다.
- **`WEB-INF`는 "브라우저가 못 여는 방"이에요.** 이 한 문장이면 왜 클래스와 설정이 거기 있는지, 왜 JSP를 거기 넣는지가 다 풀립니다.
- **의존성을 넣는다고 다 WAR에 들어가는 게 아니에요.** 서버가 이미 가진 건 빼야 합니다.
- **포트는 미리 비켜두는 게 싸요.** 8080은 자바에서 계속 겹칩니다.

## 아직 모르는 것

- IDE에 톰캣을 붙이면 이 세 단계가 어떻게 하나로 합쳐지나
- `autoDeploy`가 실패하는 경우가 있는지, 어떨 때 재시작이 필요한지
